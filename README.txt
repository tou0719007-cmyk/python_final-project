Python任务管理系统

一、项目简介
本项目是一个使用 Python 语言开发的命令行任务管理系统。

用户可以通过控制台菜单完成任务的添加、查看、标记完成、删除、搜索、筛选、统计等操作，同时支持任务数据的本地保存、HTML 报表导出以及任务统计图表生成。

本项目采用模块化设计，将任务数据结构、任务管理、数据存储、时间处理、报表生成和图表生成等功能分别放在不同的 Python 文件中，便于多人协作开发和后期维护。

二、项目运行方法
1. 环境要求:Python ，OpenCV ，NumPy ，Pillow
2. 下载项目:将项目代码下载或克隆到本地。
3. 使用终端进入项目文件夹
4. 在终端运行python main.py
5. 根据程序菜单选择功能,程序启动后会显示主菜单，用户可以输入 0~10 选择对应功能。

三、项目中的统一数据约定
为了避免多人开发时不同模块使用不同的数据格式，对部分数据进行了统一。
1. 任务状态：未完成/已完成
2. 任务优先级：高/中/低
3. 日期格式：用户输入日期时统一使用：YYYY-MM-DD
程序内部 get_time.py 会将输入转换为 datetime 对象。
在进行日期筛选和逾期判断时，通过 to_date_str() 统一转换为：YYYY-MM-DD再进行比较。
4. 任务编号：每个任务必须具有唯一的任务编号。
添加任务时，系统会检查当前任务列表中是否已经存在相同编号，如果存在则要求重新输入。

六、项目开发过程中遇到的问题及解决方法
1. Git 分支和多人协作问题
项目开始进行多人协作时，对 Git 分支、Pull Request、Merge 等操作不够熟悉，会不了解如何创建自己的功能分支，如何将代码 push 到远程仓库，如何创建 Pull Request，如何进行代码审核，如何将 Pull Request 合并到 main，成员误直接合并到 main 后如何进行处理

解决方法：
由组长对github仓库进行管理，指导成员操作并通过 GitHub 的 Commit History 和 Pull Request 记录查看每个成员的代码修改过程。

2. 合并代码时出现 Merge Conflict
不同成员同时修改 task_manager.py 等文件时，出现过代码冲突。产生冲突的主要原因是不同成员在同一个文件的不同功能区域进行修改，Git 无法自动判断应该保留哪一部分代码。

解决方法：
组长先查看冲突位置，分析双方代码分别完成的功能，然后保留需要的代码并手动整理，最后重新测试程序。通过这次过程理解了 Git Merge Conflict 的产生原因以及冲突解决方法。

3. 模块之间接口不一致
多人同时开发时，不同成员可能对函数名称、参数和返回值的理解不同。 一个模块需要任务列表，另一个模块提供的方法名称不同；不同成员对任务状态名称的写法不一致；不同模块对日期数据类型的处理方式不同。

解决方法：
在最终整合前统一模块接口：任务状态：未完成 / 已完成；任务优先级：高 / 中 / 低；日期输入格式：YYYY-MM-DD
同时统一任务管理类中的方法名称和返回数据格式。

4. 日期类型和日期比较问题
项目中 get_time.py 输入的日期会通过datetime.strptime()转换为 datetime 对象。而任务筛选和逾期判断需要进行日期比较，所以遇到了 str、date 和 datetime 三种类型之间的区别，以及不同类型直接比较可能产生的问题。

解决方法：
使用 to_date_str() 将日期统一转换为：YYYY-MM-DD然后进行比较。同时明确datetime.now()表示当前日期和时间；datetime.now().date()表示当前日期；strftime("%Y-%m-%d")可以将日期转换成指定格式的字符串。

5. 重复任务编号问题
添加任务时，如果用户输入了已经存在的任务编号，原来的判断逻辑存在循环控制问题，可能无法正确结束当前判断并重新输入。

解决方法：
使用变量记录是否发现重复编号：num_condition = False，遍历任务列表，如果发现相同编号，则将其设置为 True，结束当前 for 循环，然后通过 continue 重新进行外层 while 循环。

6. 任务数据保存问题
程序中的任务对象需要在程序退出后仍然能够保存，因此需要进行数据持久化。

解决方法：
使用 pickle 将任务对象列表保存到：data.txt，程序启动时通过 load_task() 读取数据，保存时通过 save_task() 更新数据。

7. 模块之间的代码整合问题
不同成员分别开发自己的模块后，需要将代码整合到一个完整系统中。整合过程中需要检查：函数名称是否一致，参数是否一致，返回值是否符合调用模块要求， 数据类型是否一致， 任务对象属性是否一致， 状态和优先级名称是否统一， 日期格式是否统一

解决方法：
在代码合并后进行整体运行测试，组长根据程序运行结果继续修改接口和逻辑，直到各模块能够正常协作。
